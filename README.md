# dotfiles

Themed terminal stack — switchable across kitty, tmux, oh-my-posh and fastfetch
with one command.

| Tool | Path | Notes |
|------|------|-------|
| kitty | `.config/kitty/` | `kitty.conf` includes `current-theme.conf` + `current-font.conf` |
| tmux | `.config/tmux/` | tpm; `tmux.conf` sources `current-theme.conf`, which owns the whole status bar. Plugins are **not** vendored |
| oh-my-posh | `.config/oh-my-posh/` | `current.omp.json` wired in `zsh/.zshrc` |
| fastfetch | `.config/fastfetch/` | `config.jsonc` is generated by `set-theme` from `themes/` |
| zsh | `zsh/.zshrc`, `zsh/.zsh_plugins.txt` | antidote plugin list; `.zsh_plugins.zsh` bundle is generated, not tracked |
| git | `git/.gitconfig`, `git/.gitconfig-work` | personal by default; work identity applies under `~/Workspace/Morfius/` |
| nvim | `.config/nvim/` | AstroNvim v5 template; `lazy-lock.json` is tracked so plugin versions pin |

## Themes

```sh
set-theme <name>    # tab-completes
```

Switches **eight** tools at once — kitty, tmux, oh-my-posh, fastfetch, nvim, git,
fzf, bat and eza. Each theme's files are copied to a gitignored `current-*` destination
(seeded from `dive-to-the-heart` by `install.sh`), then kitty and tmux live-reload.
Run `zeload` after — the prompt and the env-var tools are per-session.

Add a theme — drop a file with the same basename in each themes dir:

| Dir | File | Note |
|---|---|---|
| `.config/kitty/themes/` | `<name>.conf` | 16 ANSI colors, cursor/border/tab, and `background_opacity`/`background_blur` |
| `.config/tmux/themes/` | `<name>.conf` | full status bar (powerline segments) + pane/message/mode styles |
| `.config/oh-my-posh/themes/` | `<name>.omp.json` | full prompt shape, not just colors — see below |
| `.config/fastfetch/themes/` | `<name>.jsonc` | `keyColor` hex + logo `color` slots 1-5 |
| `.config/git/themes/` | `<name>.gitconfig` | diff/status/branch colors — **quote hex values**, `#` starts a comment in gitconfig |
| `.config/zsh/themes/` | `<name>.zsh` | `FZF_DEFAULT_OPTS`, `BAT_THEME`, `EZA_COLORS` |
| `.config/nvim/themes/` | `<name>.lua` | **generated** from the kitty theme — see below |

`set-theme` completes from `.config/kitty/themes/`, so a new theme shows up in tab
completion as soon as its kitty file exists.

### Prompt shapes

Each theme defines its own prompt *structure*, not just a palette:

| Theme | Shape | |
|---|---|---|
| dive-to-the-heart | minimal | `󰄖 .dotfiles   main ` |
| organization-xiii | stark, no icons | `.dotfiles — main ·` |
| twilight-town | powerline blocks | ` .dotfiles  main ` |
| castle-oblivion | powerline blocks | ` .dotfiles  main ` |
| erdtree | ornate, framed | `╭─  ~/.dotfiles ─  main` |
| frutiger-aero | rounded capsules | `󰠓 .dotfiles  main ` |

All five share the same segments: path, git (dirty/ahead/behind), root, exec time
over 2s, exit code on failure, and a clock in the right prompt. Node/Python/Go/Rust
versions use `display_mode: files`, so they appear only inside that kind of project.

## Install

Managed with [GNU stow](https://www.gnu.org/software/stow/). Repo root is `~/.dotfiles`;
the `.config` package folds into `~/.config`.

```sh
git clone <repo> ~/.dotfiles
~/.dotfiles/install.sh          # stow --restow .config  +  clone tpm
```

Or by hand:

```sh
cd ~/.dotfiles && stow -t ~/.config .config && stow -t ~ zsh
```

Then open tmux and press `<prefix> + I` (prefix is `C-s`) to install plugins.

Add to `~/.zshrc`:

```sh
eval "$(oh-my-posh init zsh --config $HOME/.config/oh-my-posh/current.omp.json)"
```

## Fonts

kitty font is swappable — `.config/kitty/current-font.conf` is gitignored (machine-local),
included by `kitty.conf`, seeded from `jetbrains-mono` by `install.sh`.

```sh
set-font <name>    # tab-completes
```

| Font | Character |
|---|---|
| `jetbrains-mono` | the default; neutral, high legibility |
| `victor-mono` | true cursive italics — good for comment-heavy code |
| `maple-mono` | rounded terminals, soft |
| `recursive-casual` | humanist and rounded; pairs with `frutiger-aero` |
| `recursive-linear` | same family, straighter — a quieter everyday face |

Live-reloads any running kitty windows (remote control is on, local socket only).
Add a font: drop a `<name>.conf` (font_family/bold_font/italic_font/bold_italic_font)
in `.config/kitty/fonts/`. Every glyph the themes use — powerline arrows, rounded
caps, branch, crown, droplet, language icons — is verified present in all of these.

## nvim

Stock [AstroNvim](https://github.com/AstroNvim/AstroNvim) v5 via the official
template — every customization file is still the template's
`if true then return {} end` stub, so nothing in `lua/` is active yet and the
colorscheme is AstroNvim's default `astrodark`.

To start customizing, delete that first line from the relevant file:

| File | Controls |
|---|---|
| `lua/plugins/astroui.lua` | colorscheme, highlight overrides, icons |
| `lua/plugins/astrocore.lua` | options, keymaps, autocmds |
| `lua/plugins/astrolsp.lua` | LSP servers and behaviour |
| `lua/plugins/user.lua` | your own plugin specs |
| `lua/community.lua` | astrocommunity language packs |
| `lua/polish.lua` | last-run vimscript/lua |

### Colorscheme

nvim uses a generated colorscheme called `dotfiles`. `.config/nvim/themes/*.lua`
are **derived from the kitty theme files** by `scripts/gen-nvim-themes.py` — the
kitty palette is the single source of truth, so colors are never declared twice.
`set-theme` copies the active one to `colors/dotfiles.lua` (gitignored) and
live-reloads any running nvim over its server socket.

After editing a kitty theme, regenerate:

```sh
scripts/gen-nvim-themes.py && set-theme <name>
```

`astroui.lua` falls back to `astrodark` when `colors/dotfiles.lua` is absent, so
a fresh checkout still opens with a working colorscheme before `install.sh` runs.

### Language support

`lua/community.lua` imports the astrocommunity packs; `lua/plugins/mason.lua`
pins every binary so a fresh machine installs the same 56 tools.

| Language | LSP | Format | Lint |
|---|---|---|---|
| TypeScript / JS | vtsls | prettierd | eslint |
| Go | gopls | gofumpt, goimports | golangci-lint |
| Python | basedpyright | ruff | ruff |
| Lua | lua_ls | stylua | selene |
| Markdown | marksman | prettier | markdownlint-cli2 |
| YAML | yaml-language-server | prettier | yamllint |
| JSON / TOML / XML | jsonls, taplo, lemminx | prettier, taplo | schema validation |
| Bash | bash-language-server | shfmt | shellcheck |
| Docker / Helm / Terraform | their LSPs | — | hadolint, tflint, tfsec |
| Rust, SQL, HTML/CSS, Tailwind, GraphQL | rust-analyzer, sqls, … | — | — |

Notes on choices that aren't obvious:

- **`ts_ls` is explicitly disabled** in `astrolsp.lua`. The typescript pack sets
  it up and vtsls supersedes it — left alone, both attach and you get duplicate
  diagnostics and double CPU per keystroke.
- **Python uses ruff, not black + isort** (the pack default). Ruff replaces both
  and is the same toolchain family as uv.
- **uv venvs resolve automatically**: `basedpyright` gets pointed at
  `<root>/.venv/bin/python` in a `before_init` hook, so imports resolve without
  activating the venv first.
- **Format-on-save is on**, with `vtsls`/`basedpyright`/`yamlls`/`jsonls`/`html`/
  `cssls` excluded — their built-in formatters are worse than prettier and ruff.
- `.stylua.toml` and `selene.toml` at the config root were previously unused;
  both are now wired, and selene only runs where a project has its config.

### AI

| Plugin | Role |
|---|---|
| `coder/claudecode.nvim` | Claude Code in nvim — agentic edits, refactors, review |
| `zbirenbaum/copilot.lua` | inline ghost-text completion |

Claude does the agentic work; Copilot does inline completion. That split is
deliberate — Copilot is fill-in-the-middle trained, answers in ~200ms on a flat
fee, whereas driving completion from a chat model costs per keystroke and lands
around a second. (`minuet-ai.nvim` can put Claude on inline completion if you
ever want it; it needs an `ANTHROPIC_API_KEY`, billed separately from a Claude
Code subscription.)

claudecode.nvim runs a WebSocket server speaking the same MCP protocol as the
official VS Code extension, and the `claude` CLI connects back to it. Pure Lua,
no Node or Python bridge.

**Claude — `<leader>k`** (not `<leader>a`, which AstroNvim already uses):

| Key | |
|---|---|
| `<leader>kk` | toggle Claude |
| `<leader>kf` | focus Claude |
| `<leader>kr` / `<leader>kc` | resume / continue session |
| `<leader>km` | select model |
| `<leader>kb` | add current buffer to context |
| `<leader>ks` | send visual selection (or add file from the tree) |
| `<leader>ky` / `<leader>kn` | accept / deny a proposed diff |
| `<leader>k?` | connection status |

**Copilot** — ghost text appears as you type. `<Tab>` resolves in order:
completion menu → Copilot suggestion → snippet jump → literal tab, so it never
shadows blink.cmp's menu navigation. `<M-w>` accepts a word, `<M-l>` a line,
`<M-]>` / `<M-[>` cycle, `<M-e>` dismisses. Disabled in commit-message and
dotenv buffers so their contents are never sent.

`lazy-lock.json` is tracked on purpose — it pins all 45 plugin versions, so a
fresh machine reproduces the same set. Commit it when `:Lazy update` changes it.

## Notes

- `direnv` is hooked; drop an `.envrc` in a project and `direnv allow` it to get
  a per-directory environment (auto-activates a uv `.venv`, pins node, scopes
  work-only vars).
- forgit's aliases are remapped to a `gf` prefix in `.zshrc` **before** the
  bundle loads. At defaults it takes `ga`/`glo`/`gd`/`gco`/`grb` from the
  oh-my-zsh git plugin, and since it loads later it wins silently.
- `GOPATH/bin` is on PATH — `go install`ed tools (`dlv`, `staticcheck`, `sqlc`,
  `swag`) were previously installed but unreachable.
- Plugins clone to `~/.local/share/antidote`, set via `ANTIDOTE_HOME`. Antidote's
  default is `~/Library/Caches/antidote`, which macOS purges under disk pressure —
  that wipes every plugin while the generated `.zsh_plugins.zsh` still points at
  the deleted paths. `.zshrc` also rebuilds the bundle when the first `source`
  line in it no longer resolves, so a purge self-heals instead of erroring.
- Assumes Apple Silicon Homebrew (`/opt/homebrew`) — referenced in `tmux.conf` and `kitty.conf`.
- Needs a Nerd Font (JetBrainsMono Nerd Font).
- `alacritty` / `helix` / `wezterm` / `spaceship` / `lvim` configs stay on disk but are gitignored.
